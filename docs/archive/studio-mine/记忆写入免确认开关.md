## 改动

新增**分范围**的两个记忆免确认开关（项目 / 全局各一个），并补 review 产出的三项加固。

- 配置 `[memory]` 新增 `auto_confirm_project_remember` 与 `auto_confirm_global_remember`，**默认 false**。
- **开关只覆盖自己那一个范围**：交互式 gate 的 approver 按范围短路；低风险新建仍走原路径，`forget` 完全不受影响，headless 行为不变。
- **加固一（用户独占）**：项目文件设置这两个键一律忽略并上报（与 `agent.write_lease` 同构）——跳过确认是用户的决定，不该由 clone 给出。
- **加固二（内容安全界）**：开关放行也要过本仓既有内容界（desc/body 必填、名字可推导、body 预算、`rememberRequestSensitive`），不通过照常弹窗。
- **加固三（收据通知）**：免询问写成的记忆 emit `memory_saved_unasked`（内核英文行 + 事实名作 `Detail`，前端给中文文案并提示 `/forget <名字>`）。

## 动机

每次"记住这件事"都要点一次确认，高频使用时很烦；但一味放宽，全局记忆又会被随手写坏。故做成**分范围**两个开关，而不是一个总开关。

## 取舍

- **范围判定不能只看显式参数**：更新时省略 `scope` 要读**被更新记忆的真实范围**（`memory.RememberWriteScope`），否则全局记忆会被项目开关放行。
- **内容安全界与分类界的区别**：原先"用户开关"与内核低风险通道**并列短路** → 开关一开就绕过内容界，凭据、邮箱这类内容会被**静默写入**。修法是开关放行也要过内容界。有意**不照搬**上游的分类界（type/重叠/activation/pinned）：本线要保留的是内容界，不是分类界。
- **设置页保持一行**：块由 `Memory.tsx` 自带外壳导出，避免设置面板被这一项撑开。
- `MemoryConfig` 抽到同包 `memory_config.go`（`config.go` 已贴 repolint 行数上限）。

## 关键文件

记忆策略与审批设置、`[memory]` 配置与渲染、`/remember-approval` 接口，以及前端 `Memory` / `Settings` 与 i18n。

## 重做记录（2026-10-16，基线 `studio-v2.41.0`）

上游在 2.39–2.41 间自带了一条**自动判定**通道：`memory.AssessRememberWrite` 只放行"新的、低风险的项目/引用事实"，其余（全局、更新、重复、含敏感内容）照旧询问。本轮按重做策略重新实现，取舍如下：

- **开关与上游判定并列，而不是替代**：gate 先走上游的低风险通道，再问本 fork 的两个开关；开关覆盖上游不肯放行的部分（全局、更新、既有同名），但仍受 `AssessRememberSwitch` 的**内容底线**约束——含凭据或邮箱的写入无论开关如何都仍然询问。
- **范围判定读事实本身**：更新省略 `scope` 时按 `RememberWriteScope` 读被更新记忆的真实范围，全局记忆不会被项目开关放行。
- **落点收进自有文件**：`internal/state/memory/remember_autoconfirm.go`（判定与范围）、`internal/session/control/remember_autoconfirm.go`（开关对、设置视图、回执与一次性标记）、`internal/frontend/serve/remember_approval.go`（`/memory/remember-approval` 端点）；`MemoryConfig` 连同 `[memory]` 段搬到 `internal/contract/config/memory_autoconfirm.go`（`config.go` 已贴 repolint 行数上限，搬走比继续加行更合适），其余上游文件只留行级挂载。
- **三项加固全部保留**：用户独占（项目文件只收窄）、内容底线、回执通知（`memory_saved_unasked` + 事实名，提示 `/forget <名字>`）。
- 验证：`remember_autoconfirm_test.go`（`internal/state/memory` 与 `internal/session/control` 两包）+ 前端 `Memory.approval.test.tsx`。
