## 本线现状（2026-10-16，基线 `studio-v2.41.0`）

重做时该主题**挂起**（上游仍在改子代理相关的锁），因此 `studio-mine` 上只有上游自带的两档（`internal/contract/config/write_lease.go` 的 `WriteLeaseOptimistic`）；本线的 `off` 档、会话内放开与运行时设置**没有移入**，待上游稳定后作为独立主题重做。以下为**旧线**（基线 2.37）的实现记录。

## 改动

让"无法声明写路径的工具"（`bash`、MCP）不再占用整个工作区，并把开关演进为三档。

- 在**收口点**改，不散点改：`workspacelease.Owner` 新增 `skipWriteSerialization`（零值=保持串行），`writeclaim` 包级加 `serializeWholeWorkspace`——一处覆盖 10 个 `WholeWorkspaceWriteClaim` 来源与 3 类调用者。
- **三档改造**：原有两个布尔收成**一个枚举** `[agent] write_lease = strict | optimistic | off`——`strict`（默认，上游行为）/ `optimistic`（只让声明了 write_paths 的写者互斥）/ `off`（本会话不取跨会话租约）。
- **吸收上游 review**：① 整区 gate 由普通布尔改**原子量**（`Overlaps` 读、启动写，是真实数据竞争）；② 该键**只允许用户配置设置**，项目 `reasonix.toml` 里设了会被忽略并上报（与 sandbox / 权限键同规）。

## 动机

无法声明写路径的工具会占用**整个工作区**，同项目的多个会话因此排队；子代理跑 `bash` 时连父代理一起被拦。

三档改造的动机：原开关只有"严格/全关"两头，中间缺一档——"说得清的写者照旧互斥，说不清的别再占整区"。这正是日常痛点（`go build`、等 CI 的 `git push`、慢 MCP 调用把整个工作区按住），也是上游 #11531 报的原始现象。

## 取舍

- **不用「传 nil Owner」**：那样会丢掉租约状态的可读性；改为"关闭时直接放行、不取租约"。
- **默认 `strict` = 上游行为**，fork 只多一个可关的开关。
- **配置键默认值要显式写真**：`[agent] serialize_opaque_writers` 零值是 `false`，`Default()` 里必须显式置真，否则老配置会静默变成"不串行"。
- **否决：再加一个布尔**——两个布尔有 4 种组合、部分无意义，语义正交性也差；改为一个枚举。
- **旧键保留识别**：`serialize_opaque_writers`（true→strict、false→off），因为用户配置里已写过；未知值一律归一为 strict（不认识的值绝不能自己放宽保护）。
- **`off` 只免跨会话那层**：会话内的 `SubagentScheduler` 仍按声明路径与写者名额排队——界面文案特意写明。
- **`optimistic` 同时放宽会话内**：它改的是 `WritePathSet.Overlaps`（包级 gate），而子代理调度与 fleet 预检用的是同一判定——**有意的语义统一**，不是副作用。
- **命名不用"默认"做档名**——那描述的是"谁定的"，不是"什么行为"。
