## 改动

让版本页并列列出本 fork 自己的发布来源，并且**两边都能安装**、提示标明来源。

- **两个来源并列，各自一把钥匙**：`Install.Mine` 声明本 fork 的目录（URL + 公钥 + 行数上限），内核把两份目录合并、去重、按版本排序；`Mine` 为空时行为与上游逐字一致。
- **验签按来源选钥匙**（`Options.PublicKey` → `VerifyWithSource`）：空值回落内嵌的上游公钥，**从不跳过验签**。
- **清单与 manifest 分两级**：目录（`versions.json`，可覆盖，放固定锚点 `studio-latest`）+ 每个版本自己的 manifest（不可变，随各版本 Release 走）。
- **资产在 Release 里保持无版本名**（`ReasonixStudio-windows-amd64-installer.exe`）：`studio-manifest` 的平台解析按这个形状匹配；带版本名会让 `platforms` 为空、updater 无从下载（本地实测确认）。
- **只列最近 3 条**（后放宽到 5 条）；"正在运行"那一行无论如何保留。

## 动机

设置页「版本」读的是**上游**的目录，而本 fork 的 `vX.Y.Z-mine.N` 发布在 GitHub Release 上、不在那份目录里 → 本机版本被标成「未发布」，页面只提示**上游**的新版本——而那个提示**可安装**：一点就把 fork 的 Studio 换成上游 Studio，且换过去后页面随二进制一起变成上游的，再也切不回来。

## 取舍

- **清单与 manifest 分两级**（而非 wails 线的单 `latest.json` + `--clobber` 覆盖）：**回退需要旧版本的 manifest 仍然可读**，覆盖式做法在这里不够用。
- **想过但没做**：只校验 sha256 而不给自己的产物签名——要在验签路径上开一个可被目录方绕过的例外，且省不下多少活。也不提上游 PR：上游明确反对"目录可配置"。
- **已知边界（已接受）**：装成上游版之后无法从页面切回——提供页面的 host 二进制随安装被替换。

## 关键文件

内核 `internal/platform/update/`（多来源目录、按来源选钥匙、行数上限与来源标记）与 host 装配点 `cmd/reasonix-studio-host`；前端版本页（来源标记、提示标明来源）；发版链（资产签名、manifest、目录锚点）。

## 备注

- **验证**：内核（两目录合并 / 每来源上限 / 来源标记 / 某一目录失败时降级 / 钥匙选择含端到端）；前端（类型、i18n、等宽字体护栏、版本页交互）；发版链本地用**临时密钥**实跑签名与 `studio-manifest`、`sed` 地址改写、`actionlint` 通过。
- **已知缺陷与修复（同日，用户实测发现）**：`v2.30.0-mine.3` 后实测报 `update: 2.30.0-mine.3 is not in the published catalog`。原因：第一版只把本 fork 目录接进**版本列表**，**安装/回退**路径仍把目录写死在上游（`internal/platform/appupdate/install.go` 的 `updater()`），验签钥匙同样没接 → "看得见、装不了"。修法（`026038aa9`）：`update.Options` 携带第二个目录；一个版本由**列出它的那份目录**回答，manifest 记下该目录的钥匙；`appupdate` 与 host 装配点把**同一个** `forkCatalog()` 同时喂给列表与安装。**边界**：`mine.2`/`mine.3` 都带此缺陷，必须**手动装一次修复版**（`mine.4`）。
- **回退**：各阶段独立提交，`revert` 即回到"只有一个上游来源"；密钥与锚点目录都是新增物，删掉无害。
