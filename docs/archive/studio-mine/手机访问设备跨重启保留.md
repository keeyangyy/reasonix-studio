## 改动

让手机（局域网 / tailnet）配对后**跨 Studio 重启免扫**，并补上界面开关。

- **进程退出不再当"关闭分享"**：新增 `Shutdown()`——进程退出只停监听、保留设备；用户主动关分享仍按"关闭即全部取消"清空。
- **重新打开分享不再当撤销**：`Open` 原调 `closeLocked()`（连设备一起清）改为只停旧监听（`stopListeningLocked`）。
- **分享开关状态与上次监听地址落盘**（`<home>/state/share-state.json`），装配时自动重开；原地址优先，地址已不在本机则回退当前可用地址；地址排序改 **tailnet 优先**。
- **凭据本身不落盘**：`device-trust.json` 只存凭据的 sha256 摘要，原子写、0600；文件缺失/损坏/摘要不可用一律读作"没有设备"。

## 动机

手机配对后只要 Studio 一重启就要重扫二维码——用户视角就是"每次开机都得重新配一遍"。

## 取舍

排查后发现是**三个独立成因**，逐个修、顺序也重要：

- 设备记录挂在 `DeviceShare.Close()` 上清空，而 `main.go` 进程退出也调 `Close()` → 每次关 Studio 都删 `device-trust.json`。
- `Open` 里调 `closeLocked()` 连设备一起清——**这才是"重启后要重扫"的主因**。
- 只记设备不够：分享开关状态与上次监听地址也要落盘。
- **凭据宁可"读作没有"**：宁可再生一次扫码，也不让一个坏文件把分享卡死。
- **测试间互相污染**：`NewDeviceShare` 回到纯内存，改由 host 装配时调 `RestoreDevices()`（config 的进程级 roots 缓存会让 `deviceTrustPath()` 落到别的测试甚至真实 home）。
- **DATA RACE**：为把持久化挪到锁外，把 `dev.view()` 与 `dev.cut()` 也带出锁，而两者都读 `pairedDevice.streams` → CI 的 `-race` 门报错。改回：锁内算结果并执行 `cut`，只有写盘留在锁外。
