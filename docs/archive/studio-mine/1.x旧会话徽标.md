## 改动

侧栏会话行标出"由 1.x 保留的旧会话"。

- **复用既有判定、不引入新判据**：`sessionstore.IsForeignSessionLog`（读事件日志首记录 schema==2）本就是"打开路径"的判据，列表只是把它带出来，两处不会不一致。
- **不碰 1.x 的文件**：判定结果缓存在本 build 自己的 `.session-legacy.json`（照 `.session-titles.json` 范式），指纹取事件日志的 size+mtime（无日志时用哨兵，日志首次出现即失效）。
- **只在唯一出口加字段**：`/tree` 是侧栏列表的唯一出口；字段 `omitempty`，老客户端读到的 JSON 不变。
- **字体用界面字体而非等宽**：徽标最初用 `var(--mono)`，撞上 `src/styles/mono.test.ts`（"等宽只留给机器事实"）——这条护栏是对的，改成 `var(--ui)`。

## 动机

本 build 读 1.x 的事件日志但从不写它（打开只读，继续对话时另存为新会话）。这类会话在侧栏与本线会话长得一模一样——判定原本只在**打开会话时**做，列表拿不到该信息，用户只能在"点错、多出一条会话"后才发现。

上游官方 issue **#12059** 正是这个诉求，并留了两条前提：**副本是打开时还是第一条消息时产生的**（答：打开只读，副本在**继续对话/一轮开始**时才建）、**列表里靠什么识别**（答：内核判定，UI 不得从文件名推断）。本实现两条都答了。

## 取舍

- **能力边界写进 PR**：只有"长成过 1.x 追加式日志"的会话会被标出；更早的、从未追加过日志的 1.x 会话与 Studio 会话无从区分，不给徽标。
- **想过但没做**：不从文件名推断（上游明令禁止）；不把标记写进会话 sidecar（会改 1.x 的数据）；不在渲染时现算（每帧读所有日志头，代价与抖动都不值）。
- **缓存绝不比它依据的日志活得更久**：指纹取 size+mtime，日志一变即失效。
