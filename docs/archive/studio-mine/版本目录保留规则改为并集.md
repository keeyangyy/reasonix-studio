## 改动

把 catalog（锚点 release `studio-latest` 里的 `versions.json`）的保留规则从「按版本号降序取前 N 条」改为**「每系列最新 mine ∪ 最新 5 条」**。

- **筛选语义**：按「去掉 `-mine.N` 后的上游 base」分组，每组取最新一条；再与「最新 5 条」取并集，保持版本降序。
- **实现位置＝本 fork 自己的文件**（零上游偏离）：
  - `tools/catalogfilter`（新，`main.go` + 6 单测）——筛选逻辑。选 Go 工具而非 workflow 内联 jq，因为**本机无 jq**、而这属发版关键路径，必须能本地单测。
  - `release-windows.yml` 写端：调 `update-versions-index.sh` 时 `keep` 传 100000（不截断），再用 `catalogfilter -recent 5` 筛选。**不改上游脚本本身**。
  - `cmd/reasonix-studio-host/main.go` 读端：`forkCatalogRows` 5 → 0（`MaxEntries` 的 0 = 不截断），否则写端保留了、内核读端会二次截回 5 条。

## 动机

本 fork 的开发方式是「对一个上游版本持续迭代，衍生 `X.Y.Z-mine.1`、`.2`、`.3`」，同系列会占掉多个名额，且**回退不到当前系列的前几次迭代**（当前 `2.35.0-mine.3` 时，`mine.2`/`mine.1` 已被截掉 → 无法回退）。用户要的是**并集**：前者保证每个上游版本都有一条可回退的历史，后者保证当前系列的最近几次迭代都在。

## 取舍

- **被否决**：把筛选写进 `scripts/update-versions-index.sh`（上游文件，会引入长期合并冲突）；用 `jq` 内联（本机无法验证）；从现有 catalog 里删条目实现「每系列最新」（catalog 本就是被截断后的产物，信息已丢）。
- **重建时发现并修正**：从全部 release 重建时，`v1.39.x-mine.*`（**1.x / Wails 线**）也匹配 `v<base>-mine.<N>`，但产物形态不同、在 Studio 里装不了 → 重建时显式排除 `major < 2`。

- **验证**：`go test ./tools/catalogfilter/` 全绿；`go build`、`go vet`（改动包）通过；repolint **clean（2623 baselined findings，零偏离）**；`actionlint` 无输出。
- **端到端实测**：13 条输入（含同系列 `2.35.0-mine.1~4` 等）→ 输出 **9 条**，正是 `{最新 5 条} ∪ {每系列最新}`。
- **发版链路实测（关键）**：`v2.35.0-mine.2` 发版后 catalog 回读 = **11 条**，其中 `2.35.0-mine.1`（同系列非最新）**被保住**——旧规则下会被截掉。
